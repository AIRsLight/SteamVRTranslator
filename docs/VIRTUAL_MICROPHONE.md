# VB-CABLE 提示音集成

本项目使用 VB-Audio 的基础版 VB-CABLE 作为游戏麦克风通道，不再自行开发、编译或签名音频驱动。内置音效为 PTT 按下时清脆的上行通知音、录音中柔和的低频白噪声、PTT 松开时清脆的下行通知音，通过 WASAPI shared playback 发送到 CABLE Input；游戏选择 CABLE Output 接收。持续白噪声使用两级 650 Hz 低通压低高频嘶声，并用 45 Hz 高通过滤直流及极低频轰鸣。实体麦克风仍供语音识别使用，不向游戏转发人声。

## 用户操作

1. 打开“VRChat 语音 → 语音输入提示音”，点击“下载 VB-CABLE”。进度条显示下载与校验状态，可以取消及重试。
2. 下载完成并校验通过后，停止服务，点击“安装 VB-CABLE”，接受 Windows 管理员授权，按官方要求重启 Windows。
3. 设备状态显示已就绪后，启用提示音。游戏麦克风首次选择 `CABLE Output (VB-Audio Virtual Cable)`，并开启游戏自己的语音。
4. “本机试听”通过 Windows 默认扬声器或耳机播放一段示例，可在未安装 VB-CABLE 时试听；“发送到游戏麦克风”通过 VB-CABLE 发送。勾选“启用回响（本机也播放提示音）”，游戏麦克风测试和正式语音输入也会同时在本机播放。再次点击正在播放的测试按钮可停止。三个阶段开关决定试听哪些声音，音量不能为零。
5. 卸载需要已下载的官方安装包。在同一区域点击“卸载”并重启 Windows；VB-CABLE 是系统共享设备，其他使用它的软件也会受影响。

已经安装基础版 VB-CABLE 的用户可以直接启用提示音，不必重新下载；需要调用安装/卸载程序时才要求下载包。旧版本升级请先卸载、重启，再安装新版本。

正式录音由 VR 或桌面 PTT 触发，提示音发往 VB-CABLE；开启回响时也会在本机播放。结束音在松开时播放，不等待识别或翻译。回响默认关闭，停止服务后修改设置，再启动服务保存生效。本机试听和回响不会更改系统默认设备，也不会转发真实麦克风。测试播放出现设备错误时会直接提示，并在日志中记录输出目标。

回响使用 Windows 默认播放设备，与游戏通道采用相同音量和阶段开关，各自生成一份完整音效。每次 PTT 开始时重新读取默认设备；如果默认设备属于 VB-CABLE，则跳过回响，避免游戏收到重复音效。本机设备不可用或播放失败会记录日志，游戏通道继续运行。松开 PTT 时两路一起进入结束音，取消、重新按下 PTT 或停止服务时清理两路播放。

## 自定义音效

停止服务后，在 PTT 按下、录音持续、PTT 松开各行点击“选择文件…”，可单独替换该阶段的内置声音。点击“内置”恢复该阶段的默认声音（开启与结束为通知音，录音中为低频白噪声），阶段开关仍独立控制是否播放。设置随下次启动服务保存；本机试听、游戏麦克风测试和回响使用相同的选择与音量。

支持 8–192 kHz 的单声道或立体声 WAV / MP3，每个文件不超过 20 MB，解码后的时长不超过 30 秒。导入时完整解码、验证并转换为 48 kHz 立体声 WAV，保存在程序目录 `sounds/voice-cues/<唯一目录>/<原文件名>.wav`，配置使用相对路径。导入失败保留之前的选择；导入成功后不再依赖原始文件。搬移或更新程序时，一起保留 `appsettings.json` 和 `sounds` 文件夹。

开启音播放一次，随后循环持续音，松开 PTT 即使开启音未播完也立即切到结束音。文件边缘有短淡入淡出，减少切换和循环时的杂音。试听会播完开启和结束音，持续音至少试听 2 秒，较长文件试听一整段；随时可以点击停止。

服务启动时预加载音频，PTT 播放期间不读取文件；游戏与回响共享解码结果，各自维护播放位置。自定义文件丢失或损坏时，试听直接提示错误，正式服务仅将有问题的阶段回退为内置音效并写入日志，不影响语音识别。

- 版本：Pack45（2024 年 10 月），基础版，不含 A+B 或 C+D。
- 文件大小：`1318877` 字节。
- SHA-256：`B950E39F01AF1D04EA623C8F6D8EB9B6EA5C477C637295FABF20631C85116BFB`。
- 缓存位置：程序目录下的 `drivers/vb-cable/VBCABLE_Driver_Pack45.zip`。

下载先写入临时文件，完整大小和 SHA-256 校验通过后才替换缓存。网络请求失败最多尝试三次；取消和失败会清理当前临时文件。官方若更换同名包，需要先核对新包及签名，再更新代码中的固定大小和摘要，不应取消校验来绕过版本变化。

每次安装/卸载都重新验证 ZIP，再解压到新的 `setup-<随机值>` 目录。解压限制文件总量、大小与路径，不重用之前解压的可执行文件。随后使用 WinVerifyTrust 验证官方 `VBCABLE_Setup_x64.exe` 和 `vbaudio_cable64_win10.cat` 的可信签名。保留所有官方包文件和 readme，不修改 INF、驱动或签名。

用户明确点击安装/卸载后，程序使用 `runas` 调用官方安装器，参数分别为 `-i -h` 和 `-u -h`。下载操作没有管理员权限，也不会触发安装。安装器可能派生其他进程，所以保留解压文件；安装器退出不等于设备已经就绪，实际启用仍以音频端点检测为准。当前应用的自动安装入口面向 Windows 10/11 x64。

## 设备自动连接

通过 SetupAPI 查找硬件 ID 完全匹配 `VBAudioVACWDM` 的基础版驱动。优先读取端点的 `ControllerDeviceId`，匹配完整驱动实例 ID（包括 Windows 常见的 `{1}.` 控制器前缀）；其次从端点实例沿 Windows PnP 父设备查找；最后尝试音频设备拓扑。单个属性或拓扑接口读取失败不会阻止其他识别路径。检测不依赖用户可修改的设备显示名称，不会把普通扬声器、Voicemeeter 或 CABLE A/B 识别为目标。

播放端和录音端必须同时活动且属于同一个驱动实例。Pack45 有正常扬声器端和 16 声道端，优先选择正常扬声器端。发现多个无法唯一确定的配对时，保持提示音禁用。每次 PTT 都重新探测；窗口每 3 秒刷新设备状态，设备消失时停止提示音。

WASAPI 使用共享模式，按设备支持的格式适配；用户无需手动配置声道和采样率，也不必安装混音软件。游戏是否开麦、语音门限和降噪仍由游戏控制。

如果 Windows 中能看到 VB-CABLE 而程序未就绪，点击“刷新”，再到“诊断”查看 `[vb-cable] 设备检测`。日志记录驱动实例、端点名称/方向/活动状态、使用的识别路径及失败代码，便于区分端点被禁用、输入输出不完整、无法关联驱动和接口读取失败。启动与检测结果变化时自动记录，定时检查不会重复刷屏。

检测到端点明确属于其他声卡时，直接跳过其音频拓扑。单个设备的 COM、接口转换或音频库空引用异常会被隔离，不会清除已找到的 VB-CABLE 配对。已移除的历史端点不参与扫描；仍会检查活动、禁用和未插入的现有端点。

## 安装前后默认设备

VB-CABLE 官方文档说明，新安装的音频驱动可能被 Windows 自动设为默认设备。程序在安装前记录播放/录音各角色的默认端点，并在 VB-CABLE 就绪时检查。如果默认端点被改为 VB-CABLE、原端点仍有效且原先不是 VB-CABLE，则尝试恢复原端点；用户改选的其他设备不被覆盖。

该快照可在重启后使用，有效期为 24 小时。恢复操作使用 Windows 的非公开 PolicyConfig 接口，因此属于尽力恢复；不兼容或失败时会明确提示。程序不会把 VB-CABLE 主动设成系统默认麦克风，不会更改游戏配置、证书存储或 Windows 启动策略。

## 构建与验证

普通 `dotnet build/test` 和 `build.ps1` 即可，无需 WDK、C++ 编译器或自购驱动签名证书。发布包只包含应用和本说明，VB-CABLE 在用户点击下载时从官网获取。

自动测试覆盖下载校验、取消及清理、失败重试、并发请求、安装前重新验证、签名失败、解压路径限制、设备配对、默认设备恢复条件及提示音启用前置条件。UI 布局测试覆盖中、英、日界面。

真实驱动安装、卸载、重启后端点识别、默认设备恢复及游戏接收，需要在安装 VB-CABLE 的 Windows 机器上验证；只通过自动测试不能证明这些系统交互已完成。下载与签名校验可以单独验证，不需要安装驱动。
